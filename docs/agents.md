# 项目经验沉淀

## 2026-07-28 · Next 桌面壳与恢复事务经验

- 保留 Route Handlers 的 Next 应用桌面化时，Electron + standalone 能复用现有 Node 边界；不要为了安装体积未经实测就拆成 Rust 与 Node 双运行时。
- 自定义协议提供稳定 IndexedDB origin，但真实服务仍应只监听随机 loopback；主进程代理注入一次性令牌，服务端校验后立即移除。
- 桌面运行时、standalone 与静态资源必须在启动前核对清单。Electron 43 的 V1 fuse wire 已包含 `WasmTrapHandlers`，应在 Forge `afterComplete` 中使用兼容该 wire 的官方 `@electron/fuses` 逐项显式设置；不要受旧 Forge Fuses 插件的 peer 范围限制而漏配新 fuse。
- Windows 打包时，Forge 生成的反斜杠 glob 可能让 fast-glob 扫描整个工作区；仅在桌面构建预加载脚本中把 glob 规范化为 `/`。ASAR 完整性资源使用 Win32 Resource API 写入，避免 JavaScript PE 重写带来的峰值内存。
- Electron 官方 Windows 包未附带 `browser_v8_context_snapshot.bin` 时，必须关闭 browser-process-specific snapshot fuse 并保留标准 `v8_context_snapshot.bin`；开启缺失的专用快照会让安装版在主进程启动前直接失败。
- 跨 IndexedDB 恢复无法获得原生跨库原子性，应在独立传输库持久化输入和旧快照，按库提交并在失败或下次启动时回滚。
- 开发 fixture 应在 controller 挂载前分流，表格对齐应使用内容语义类，不得用整表居中或 `nth-child` 推断。
- 对话 Composer 的“+”只收纳低频附件、媒体与知识工具；语音、实时通话、模型和推理保持一级入口。斜杠指令只管理输入期瞬时状态，模型目录、推理运行值、录音内存边界和首条消息前的工具阻止规则继续复用原 controller 与组件。
- 同仓维护 Web 与 Electron 时，PR 门禁验证共享业务和桌面契约；安装包只在 Windows 目标 Runner 生成，版本标签必须与 `package.json` 一致并先创建 Draft Release，避免 Web 合并意外发布桌面版本。
- Electron 与内置 Node 归档应在准备阶段固定版本并校验官方 SHA-256；Forge 显式消费 npm 安装缓存中的 Electron ZIP，避免已缓存依赖仍在打包阶段重复访问外网。


## 2026-07-18 工作台交界经验

- 桌面抬升面不要同时叠加发丝边框、整宽顶部渐变和外阴影；缩放后会形成明显直线与圆角残块。
- 相邻不透明 surface 的弥散层应在接缝处先回到同一实色；需要结构边时只让 `<main>` 绘制一次。模糊外阴影即使使用负扩散也会沿圆弧形成楔形，应改用避开圆弧的直线内侧渐隐。
- 顶栏、侧栏与主区零留白相交时，只允许 `<main>` 绘制顶部和左侧 1px 共边；相邻宿主不得重复边框。左上圆角禁止添加内外阴影、高光或渐隐，避免弥散背景下产生楔形和残块。
- 工作区可隐藏原生滚动条，但必须保留 `overflow-y: auto` 及滚轮、触控、键盘和程序化滚动；设置侧栏等独立滚动面按自身需要保留滚动条。
- 半透明共边与弥散背景并存时，不能只依赖 `background-clip`，也不能让矩形 frame 把渐变填进圆角外侧。应由带相同圆角的 frame 承载弥散、layout 保持实色，`<main>` 只绘制共边和圆角。

## 2026-07-16 学习闭环、SDK 与声明式扩展经验

- 长期学习满意度不能只靠通用记忆。稳定偏好进入记忆；掌握、错因、复习和下一步行动必须从可观察数据动态派生，并携带可追溯证据 ID。
- “模型讲过”不等于“学生掌握”。辅导闭环至少包含学生动作和确定性微测；复习间隔由微测结果计算，禁止用模型置信度直接更新掌握状态。
- 官方 SDK 应放在 `ProviderTransport` 内部，不能替换业务 adapter。SDK 的默认重试必须显式关闭，避免一次用户动作产生重复计费；自定义代理继续保留原始 HTTP URL 语义。
- 浏览器相机、屏幕和未来眼镜应共享最小 `VisionSourceAdapter`。重复帧判断只使用不可逆低分辨率指纹，原始帧只留内存，仓储再加一层 Data URL/Blob URL 拒绝守卫。
- 第三方个性化先开放声明式数据而不是任意代码。严格 schema、未知字段拒绝、路径与 MIME 白名单、内容摘要、非对称签名、独立数据库和可回滚生命周期是 V1 的最低安全边界。
- 扩展效果必须组合现有主题、人设和模块；需要执行能力时使用 MCP。不要为了“像 Obsidian”而在 Web 主线程引入任意第三方脚本。
- Node 22 的 `--experimental-strip-types` 不支持 TypeScript 构造函数参数属性；参与契约测试的服务类使用显式字段和普通构造函数赋值。

## 2026-07-15 AI 活动与记忆经验

- 全局 AI 活动不应模拟第二套聊天界面：对话事实留在消息流，测试与后台任务按展示意图进入最小宿主。
- Google 官方 endpoint 版本必须由官方主机规范化，自定义代理路径不得被强制改写；错误路径不能写进契约测试形成“测试通过的生产 bug”。
- 跨厂商迁移只使用可见消息、附件摘要和必要工具结果；隐藏推理、thought signature 和厂商状态不是可移植会话事实。
- 自动记忆应采用确定性隐私门槛：秘密丢弃，敏感/冲突/学习状态待处理，高置信稳定内容才自动生效，并保留可撤销修订。

## 2026-07-15 模型目录与对话轮次经验

- 原生 `datalist` 会按输入值过滤候选，不适合作为“当前值可编辑但仍需浏览完整目录”的模型选择器；共享 listbox 必须把选中态与搜索态分离。
- fallback 是占位而不是在线缓存。目录加载必须显式携带来源、完整性和过期状态，否则默认能力会永久停在静态子集。
- 厂商分页游标、鉴权和能力元数据必须留在服务端目录 adapter；客户端只消费归一化条目，未知模型不猜能力。
- 时间戳不足以确定消息顺序。新记录使用 `turnId/sequence`，历史记录使用用户优先的稳定回退，工具步骤按可见性分层。

## 2026-07-15 Google 双协议与品牌选择经验

- 厂商级 `apiFormat` 不能代表一个厂商全部模型；协议差异必须由精确模型 descriptor 或在线目录驱动，并在 adapter registry 集中执行。
- 协议探测只适合显式连接测试。普通生成遇错后切换 endpoint 会造成重复计费和重复副作用，因此禁止双发。
- Google Interactions 与 GenerateContent 的字段命名、流式事件和状态留存完全不同；类型与契约测试必须断言两组字段互斥。
- 默认能力选择器的品牌图标是展示层派生值，不应污染 `{ connectionId, modelId }` 原子持久化结构。
- 同厂商的模型目录和生成 endpoint 可能使用不同鉴权；MiniMax 必须分别测试 `X-Api-Key` 与 Bearer。

## 2026-07-15 粉笔账户导入与品牌资产经验

- 社区品牌资产必须固定包版本、本地固化并记录校验值；Lobe Icons 是用户指定的 MIT 社区来源，不得写成厂商官方品牌包。
- 粉笔账户同步属于明确标注的实验直连，只允许固定题库域名和已登记路径。Cookie 仅本机加密，服务端不持久化；任何结构漂移都必须回退到官方导出文件草稿链路。
- 外部题目稳定 ID 优先用于去重，题干指纹只作兜底；账户同步、文件解析和粘贴解析都必须先落草稿，确认前不得写错题库。
- Gemini REST 字段必须按 GenerateContent 原名映射；Priority 使用 `serviceTier`，thinking level 与 budget 互斥，错误展示必须脱敏但保留可行动分类。

## 2026-07-14 设置与真实额度经验

- 编辑连接时“已保存档案”和“当前草稿”必须是两个状态域；密钥可以在客户端边界按需复用，但 Base URL、厂商、模型和测试展示意图必须来自草稿。
- React 合成事件的 `currentTarget` 不得在函数式状态更新器中延迟读取；先复制 `value` / `checked`，否则生产构建可能在事件回收后触发整页错误边界。
- 额度开关不是普通表单字段。启用必须立即落库并接入可见性、在线、过期、并发、超时和旧快照保留的运行时生命周期。
- 额度视觉层必须区分比例环和状态环：只有可靠分母时计算比例；刷新图标只表示动作，厂商 Logo 只表示品牌，配置入口不得取代刷新主操作。
- MiniMax 国内/国际站和套餐类型必须显式保存，不能从 Key 猜测。文本与多模态统一走官方 Anthropic-compatible Bearer 协议；M3 精确声明图片、视频和运行档位，M2.x 禁止继承这些能力。
- 个性化记忆必须采用 pending/active 边界；AI 不得直接激活建议，只有确认后的短记忆可按范围确定性选取并限制上下文长度。
- 危险数据操作按业务域拆分并显示真实数量；完整重置必须输入确认文字，AI 连接页不得混入业务数据删除。
- tooltip 的可访问描述与可视浮层必须解耦：`aria-describedby` 常驻，视觉提示由 hover/用户键盘意图触发，程序化焦点和触屏不触发。
- 弹层换层不能让外壳承担滚动；先清零 viewport，再用真实尺寸决定滚动，可消除右侧滚动条闪烁。
- 普通推理 Key 与 Admin/Management 账单凭据必须分库存储和逐项加密；无稳定官方 API 的厂商只允许 manual/unsupported。
- 品牌资源必须记录来源、核验日期和许可说明。官方明确限制第三方 Logo 时使用文字缩写，不得复制受限图形或回退通用机器人图标。

## 2026-07-12 对话拖拽与连接简化经验

- 嵌套对话树不要依赖原生 HTML5 `draggable`；拖拽上下文应限制在树组件内，多种 sensors 共用数据契约，repository 保留最终合法性判断。
- 模型列表的点击本身就是明确选择，不要再增加确认按钮；来源、核验日期和协议状态属于诊断信息。
- 连接档案和默认用途是不同状态域：前者保存鉴权与 endpoint，后者保存连接和模型。
- 七家重点厂商必须进入显式 `ProviderAdapter` 注册表，未核验厂商只能走兼容边界。
- MiniMax 文本优先使用官方推荐 Anthropic-compatible endpoint；语音仍使用原生 T2A。

## 2026-07-12 连接模型解耦经验

- AI 连接只承担鉴权、endpoint 和能力；业务调用必须显式解析 `AiRuntimeModelSelection`，不得重新读取历史 `connection.model`。
- 会话模型与后台能力默认模型是两个状态域；已有会话选择优先，空白对话先恢复最近会话选择，没有历史时再使用对应能力默认连接与模型。
- MiniMax 官方旗舰回退为 `MiniMax-M3`；在线 Models API 成功时展示账户可用的全部未弃用模型，静态目录只用于失败回退。
- 嵌套树的根目录 drop target 必须在拖拽期间固定可见，父子 drop handler 必须阻止错误冒泡并清理高亮。

## 2026-07 架构再加固

- AI 辅导的摄像头、屏幕共享和截图属于对话工具，不再作为侧栏主模块重复暴露；历史 session 数据通过次级入口继续访问。
- 错题、知识与薄弱分析共用 `LearningDataExplorer` 的筛选作用域；板块筛选不得同时出现在侧栏与内容区。
- 模块交给新对话时使用 `ConversationLaunchContext`，保持空白草稿不落库，并且只持久化脱敏摘要。

- 主工作台不得直接读取 conversation repository；对话快照、命令搜索和快捷键统一由 `useReviewConversationController` 管理。
- 新领域类型优先从 `app/types/domains/*` 引用；`app/types/review.ts` 仅作为渐进迁移兼容出口。
- Dexie 版本迁移应放入 `app/db/review-db-migrations.ts`，保持单事务、幂等和可独立测试。
- 架构约束必须进入契约测试，至少覆盖 workspace 预算、动态加载和循环依赖，不能只依赖评审约定。

## KnowledgeWorkspace 瘦身经验

- 知识资料列表的渐进渲染、批量选择、批量删除和导出范围计算应保留在 `useKnowledgeListController`，不要重新塞回 `knowledge-workspace.tsx`。
- Obsidian repository 与知识演进 AI service 属于知识库低频重服务，只能在刷新或用户动作中通过动态 `import()` 加载；React 状态仍只保存可序列化 snapshot、mapping 和 proposal。
- Obsidian Vault 位于知识库，AI 额度使用独立设置项；AI 连接页只管理模型调用连接，不再承载额度配置或数据清理。

## 专项学习与插件化经验

- 顶层工作台采用 Codex 式入口：新对话、搜索、已安排、插件和项目；“公考”是首个专项学习项目，后续专项通过 `StudyDomainDefinition` 注册，不再把功能平铺到主侧栏。
- 专项首页要优先展示学习链路和下一步，而不是只罗列模块；公考当前链路是导入/错题、知识沉淀、知识训练、AI 辅导、已安排复盘和 Obsidian 输出。
- “已安排”是原本本地自动化的产品入口；底层 automation 类型、表和仓储可继续复用，命名调整不得为了 UI 文案升级 Dexie schema。
- 粉笔导入属于“公考 → 导入资料”的内部 `ImportProviderPlugin`，不再作为主导航板块；UI 只能消费适配器结果和诊断，不能重新直接绑定粉笔 parser。
- 内置集成页采用紧凑目录式 UI，只显示真实可打开的应用内能力；不得用静态 `installed`、无处理函数的安装或禁用按钮制造虚假生命周期。
- 插件目录字段必须来自注册表，不能在 UI 中硬编码 provider 特例；运行态摘要只接收脱敏数量与连接可用性，不能读取 prompt、Vault 正文、截图或完整厂商响应。
- AI 额度 provider 采用 CodexBar 式 descriptor/fetch strategy 思路，provider 卡片、官网入口、状态页、刷新周期和 unsupported 原因都从注册表读取，通用 client 不写厂商账单分支。
- MCP 必须从插件目录移出，单独放在 `设置 → MCP`；本轮只保存 server 配置和 discovery 摘要，真实 tools/resources/prompts 调用后续通过 conversation run/step 展示。
- AI 对话面板按 Codex 风格展示会话、消息、composer 摘要和工具链；点击“新对话”只进入空白草稿，发送首条消息后才落库。工具链默认在消息流中折叠为“已运行 N 条命令”，会话和项目通过 IndexedDB v14 持久化，但只能保存可见消息、附件摘要、run/step 和 usage。
- 公考项目在侧栏默认只显示一个项目入口，模块和六大板块必须收进公考内部折叠入口；板块只作为错题筛选，不再与项目并列。

## TutoringWorkspace 瘦身经验

- 实时辅导的媒体源、关键帧采样、语音转写/朗读、本地草稿和当前轮次提交应保留在 `useTutoringSessionController`，`tutoring-workspace.tsx` 只做 tab、计划、关联和设备视图接线。
- 辅导仍必须遵守能力边界：纯文本轮次使用默认文本连接，携带关键帧时使用默认多模态连接，朗读只使用默认语音连接；缺连接时明确提示，不做本机或跨能力回退。

## AI JSON 解析经验

- 模型返回 JSON 必须通过 `app/services/ai-json.ts` 统一清理和解析；业务 service 不再手写 markdown fence 清理、对象/数组截取或裸 `JSON.parse`。
- 统一 helper 只负责解析稳定性，不改变 prompt 契约和字段 schema；字段缺失、空数组和业务归一化仍留在各自 service 的 normalize/validate 逻辑。

## 数据性能与发布验收经验

- 没有真实慢查询证据时，不为性能或列表切片升级 Dexie schema、不新增索引；通用 AI 会话持久化是业务建模升级，v14 只能新增会话/项目相关表。
- 真实 Vault 验收保留在人工 smoke：connect、sync、conflict、proposal confirm 四条路径必须逐项记录；CI 只验证契约和 mock provider，不接真实 Vault 或外网模型。

## AI 连接收尾经验

- 默认连接 ID 不能只在写入时校验；编辑连接能力后也必须在 repository 读取边界归一化，否则 React 会继续拿到能力不匹配的档案。
- 连接级客户端必须接收明确任务用途，并在解密密钥前校验能力。设置页测试也属于真实调用方，不能绕过该客户端。
- 流式输出只能在 provider adapter 层解析厂商事件，业务 UI 消费统一 `status/delta/usage/done/error`；结构化 JSON 任务仍等完整内容结束后走 `ai-json.ts`。
- AI 活动可视化按 run/step 展示工具链阶段、短文本片段和 usage 摘要，不得持久化 prompt、截图、完整上下文、Vault 正文或厂商原始事件。
- AI 连接模型选择使用下拉列表加手动模型 ID 兜底；模型能力和推荐状态作为说明展示，不再把推荐模型铺成按钮列表。
- 额度查询必须做成独立插件适配层，账单凭据与普通模型 Key 分开保存；没有官方账单 API 时只显示 unsupported/manual，不抓取网页后台。
- 额度 UI 采用紧凑厂商卡展示用量条、周期、刷新时间、来源标签和 unsupported/error 徽标；OpenAI 官方接口没有余额字段时必须明说，不得伪装余额。
- 额度插件配置使用本地加密存储即可，不为这类小型设置升级 Dexie schema；无慢查询证据时继续遵守不新增索引约定。
- 兼容旧表不仅要处理首次迁移；默认文本连接的模型、地址或密钥变更也要同步，清空或移除文本能力时则必须删除旧记录。
- 缺少默认连接时可以保留不发起 AI 请求的本地保存能力，但提示必须明确说明降级结果，不能伪装成 AI 摘要成功。
- 共享壳层接收状态文案时必须实际渲染并声明 `role="status"`；只把提示保存在上层状态会造成业务逻辑正确但用户完全不可见。
- `next/font/google` 会在生产构建阶段联网；要求离线可构建时，应提交官方字体和许可证并使用 `next/font/local`。

## 本次决策

- 外部知识库接入要把目录句柄封装在 adapter/repository；React 只接收序列化快照，避免权限对象进入组件树。
- Obsidian 双向同步必须保存基础、Vault、应用三方哈希；双边变化不得按时间戳猜测覆盖顺序。
- AI 自进化使用“自动收集、手动生成、确认写入”，只维护标记区块和 Wikilink，不覆盖用户手写 Markdown。
- 参考边框自带透明余量时应裁有效像素并保持目标比例，不能依赖 `object-fit` 掩盖蓝带悬空。
- 定制人设的业务模式与展示密度分开建模：`personaDisplayMode` 继续表示默认/定制，`customPersonaViewMode` 只表示闪卡/头像，并由 repository 归一化。
- 用户提供了明确边框参考时，采用确定性近白背景透明化，避免生成式重画改变卷草细节。
- 屏幕共享只扩展生命周期和错误反馈；媒体流留在浏览器内存，AI 继续只接收低频关键帧。
- 像素级复刻优先使用多参考图透视校正和像素共识提取，避免手绘 SVG 的轮廓漂移。
- 原图底边蓝色属于卡框结构，提取时以独立蓝色掩码限制在下缘，不把人物背景色带入透明资产。
- 默认人设与定制卡背字段和滚动需求不同，拆分组件比继续增加模式分支更易维护。
- 角色音色属于人设实体；旧全局值只做一次性迁移，防止用户删除后被回退逻辑重新注入。
- 主题差异应由数据预设表达，禁止使用主题名称触发隐藏样式分支。

## Obsidian 桥接收尾经验

- File System Access 的目录句柄可以持久化，但权限恢复必须保留真实点击的用户激活；React 只消费恢复状态，句柄继续封装在 repository。
- 托管根目录不存在不能按空 Vault 处理，否则会把全部映射误标为断开；同步必须在完整遍历和重复 `review-id` 预检后才提交新基线。
- 本地新建且尚未映射的知识资料也属于 Obsidian 可用性边界；同步应在预检后为它生成确定性托管路径和 `synced` 映射，避免用户以为“立即同步”只导入不导出。
- 冲突按钮展示的内容可能在用户确认前再次变化，覆盖前必须复读文件并同时校验 Vault 与应用哈希。
- 文件系统和 IndexedDB 无法组成同一事务；先写带稳定 `review-id` 的确定性文件，再事务提交本地状态，可让提案失败后安全重试。
- `create`、`merge`、`link` 必须保持不同写入语义，尤其 `link` 只能维护托管链接和来源引用，不能借机改写正文。
- 知识演进不得把目标知识自身作为唯一来源或生成指向自身标题的 Wikilink；service 先过滤，repository 写入前再次防御。
- `KnowledgeEntry.nextReviewAt` 必须保持 `YYYY-MM-DD`；Vault 导入或迁移不能把完整 ISO 时间戳送入 `formatShortDate()`。
- Obsidian 图谱由同步后的 mapping 和 Wikilink 派生；React 只持有可序列化 `ObsidianGraphSnapshot`，AI 提案只接收节点/边摘要，不读取未授权 Vault 全文。
- CI 只验证静态质量、契约和生产构建；真实 Vault 与 AI 密钥必须留在本地浏览器验收，不得写入 Actions secrets 或测试夹具。
- 契约测试使用 `--experimental-strip-types`，GitHub Actions 与本地交付基线应使用 Node.js 24.20.0，避免 Node 20 无法识别该运行参数导致质量门误失败。

- 知识演进确认闭环必须区分 `create`、`merge`、`link`：`merge` 只能替换显式 AI 演进区并维护摘要、标签、托管链接和来源引用，`link` 只能维护 Wikilink/sourceRefs；两者确认前都要复读 Vault 并校验过期 hash，写入失败后 proposal 必须保持 pending 以便重试。
- 知识演进生成必须返回可见诊断：解析数量、过滤数量、空结果原因和过滤说明都要在 UI 可见，不能只显示空状态。

- 顶栏不要再用全宽底边线重复分割工作区，桌面侧栏也不要保留会从工作区圆角旁露出的全高右边框；对话内部满高容器应继承壳层 `100%` 高度，禁止重新用视口减顶栏高度，避免边框参与计算后产生亚像素溢出并破坏圆角贴合。
- 开启弥散时，工作区保持不透明 surface，但必须重新叠加 `--chrome-window-diffuse`，否则通用壳层会遮掉主题效果。
- 外层抬升面不能绑定 `.conversation-shell-content` 等业务类名；应由 `WorkspaceShell` 的结构化 surface 统一承载，并让主应用与设置工作台默认实际启用。
- 通用壳层只负责边界几何，内容 padding、滚动和满高职责继续留在各视图类名中，避免 Dashboard、设置和对话出现双重间距。
- 蛇形学习路径应拆段表达顺序渐变，并在真实浏览器中按 SVG 屏幕坐标验证节点中心距离，而不是只比较设计常量。
- 移动临时抽屉状态不得复用桌面持久化折叠偏好；关闭态同时使用 `aria-hidden`、`inert` 和明确的移动端 CSS 选择器，避免高优先级桌面规则继续拦截点击。
- 空白对话只保留一个任务提示，输入区贴近底部安全区；桌面抬升面样式必须在移动断点用同等或更高特异性的规则完整取消。
- 公考首页主操作由纯函数按可观察状态排序；配置健康、学习路径和旧详情能力使用结构化数据与原生 disclosure，避免把业务判断塞回展示组件。
- 截图回归应等待抽屉过渡完成，并分别保存展开侧栏的桌面对话、关闭抽屉的移动对话以及桌面/移动总览，防止无障碍隐藏先于视觉动画造成误判。

# 2026-07-21 已安排外部采集经验

- 外部搜索工具只负责发现 URL；正文必须重新经过应用自己的 SSRF、origin、DNS、重定向、大小和内容类型边界，不能信任 MCP 返回内容。
- 运行期标准化文档与可持久化证据必须是两个类型；前者可含受限正文供本次模型调用，后者只保留有限摘录、URL 与哈希。
- 可信度必须由确定性函数计算。模型只给出整理稿、证据 ID 和复核结论，不能直接决定分数、等级或是否可确认。
- 缺复核模型是允许的产品降级，不是静默回退：最高 B，并在运行收件箱和提案页显示“未交叉复核”。
- 文件系统批量写入不能伪装事务；正确闭环是统一预检、顺序写入、成功即 accepted、失败保持 pending，并让重试复用稳定 proposal ID。
- 采集配置作为 `AutomationDefinition` 可选字段保存即可；没有查询索引需求时不得为了新字段升级 Dexie v16。

# 2026-07-23 P1 学习列表经验

- 已有列表控制器能够承担 80 条渐进显示时，不要为视觉改版引入数据网格或虚拟列表；只拆展示组件即可降低迁移和无障碍成本。
- 移动端固定详情位于主工作区的层叠上下文时，应从 `--chrome-topbar-height` 下方开始；仅提高 `z-index` 仍可能被应用顶栏截获点击。
- 工作台已有页面标题时，业务视图只补充说明和指标，避免桌面和移动重复标题；移动顶栏应显示当前视图名。
- 知识库的内化、Obsidian 和模板工具是次级能力，主列表与编辑器应优先出现在首屏，次级工具放在列表之后或 disclosure 中。

# 2026-07-18 主题字体与弥散边界经验

- 内置主题的字体栈应由独立常量统一维护；repository 只迁移精确匹配的历史内置值，任何未知字符串都视为用户自定义并保留。
- 等宽字体必须通过 `--app-code-font` 进入代码预览、标识符和凭据输入，局部 CSS 不得重新声明 `ui-monospace` 栈。
- 顶栏可以在不透明底色上叠加低透明度弥散背景，但不得恢复透明窗口或 `backdrop-filter`。
- 工作区共边与圆角不使用伪元素阴影，避免相邻方向效果叠加成可见残块。

# 2026-07-13 紧凑模型菜单经验

- 钻取菜单每次只渲染当前层。用绝对定位把新层覆盖在旧层上会留下可 Tab 聚焦的隐藏控件，也会迫使两档菜单继承七档高度。
- 菜单宽度按信息密度分层：厂商、模型、普通运行和预算层不能共用最宽尺寸；高度必须随内容变化，只在超过可用视口时内部滚动。
- 模型选择乐观状态必须以 `conversationId` 为键，并按点击顺序串行写 repository；空白草稿与持久化会话不能共用同一份无键状态。
- tooltip 是能力说明的次级入口，不应为每个选项常驻圆形 `i`。共享实现需要 `role="tooltip"`、`aria-describedby`、键盘焦点、触屏焦点和视口碰撞处理。
- 运行菜单和模型菜单应使用真实 radio 语义；E2E 通过角色、可访问名称和稳定 `data-*` 状态定位，不再以组件源码正则或 CSS module 类名证明交互行为。
# 2026-07-23 P1 辅导与面试当前轮次经验

- 实时辅导应作为 `conversation.kind` 的按需能力接入可见对话链，而不是恢复独立主模块；历史页只保留记录、计划与资料关联。
- 跨表关联使用可选 `conversationId/conversationMessageId` 和确定性主键，可以在 Dexie v16 不加索引的前提下实现幂等重试；按关联读取时使用主键或内存过滤，不能假定新增索引。
- 对话模型必须由会话选择显式传给辅导服务，连接档案只提供鉴权和 endpoint。媒体输入只随当前请求存在，repository 在写入边界继续拒绝 Data URL 与 Blob URL。
- 桌面信息侧栏和移动底部抽屉可以共享无业务状态的布局组件；焦点锁定、Escape、滚动锁定和焦点恢复统一实现，辅导与面试的阶段、评分和动作保持 feature-local。
- 面试评分只能消费已保存 evaluation；当前阶段使用 `aria-current="step"`，移动端不能因隐藏桌面头部按钮而丢失“结束并复盘”的主操作。
# 2026-07-23 P2 已安排与设置经验

- 已安排的列表、收件箱、编辑层与移动抽屉应共享一个专用展示 controller；摘要必须从任务/运行快照确定性派生，不能在组件内维护第二份计数。
- 移动页签只切换可见面板，不清空筛选或选择。桌面侧边编辑器与移动全屏编辑器共享表单，但焦点锁定、Escape、滚动锁定和焦点恢复属于覆盖层边界。
- 设置分区必须继续使用工作台恢复导航的受控状态；移动 `<select>` 只是同一状态源的另一种入口，不能镜像到内部 state。
- 连接列表只显示 provider、名称、URL、状态和测试摘要；密钥只留加密仓储。默认能力始终分离连接与具体模型，不从未知模型名猜测能力。
- 视觉稿含示例数据时，真实空数据库截图应以明确空状态替代伪造记录；结构、密度、主操作与响应式关系仍按确认稿验收。
# P3 UI/UX 收口经验（2026-07-23）

# P3 ReviewWorkspace 架构收口经验（2026-07-23）

- 根工作台应只负责 controller 组合与 view router 渲染；学习和知识的筛选、选择、队列、计时与动作分别归领域 controller，避免根组件再次成为跨域状态容器。
- route component 只消费显式 controller 类型并装配视图，禁止直接导入 repository/service。需要 Vault 或 AI 服务的动作继续在领域 controller 内按需动态加载。
- 低频视图的 `next/dynamic` 必须保留在模块顶层并使用显式 import 路径；加载占位不得读取业务数据。
- 预算采用硬性契约：根组件 150 行、顶层 controller/router 300 行、领域 controller 和任何 React component 500 行；同时扫描循环依赖、旧 `stats` 路由和 Dexie v16。
- 纯架构重构仍必须跑完整 E2E 与双端视觉回归；不能用类型与单元契约代替真实交互、控制台和横向溢出检查。
# 2026-07-23 · P0 本机 API 安全闭环

- Route Handler 必须通过 `server/http/route-security.ts` 读取有界 JSON、校验浏览器 Origin 并返回结构化脱敏错误；不得重新直接调用 `request.json()`。
- Next 生产服务器可能把内部 Request URL 规范化为 `localhost`；同源校验应以浏览器 Origin 与实际 Host 共同判断 loopback 入口，不能把 `127.0.0.1` mock 请求误判为跨来源。
- API 错误固定为 `{ code, message, requestId, retryable }`，SSE 可选携带同字段；成功 JSON、二进制和 SSE 都应返回 `X-Request-Id`。
- 外联地址禁止 URL 内嵌凭据；Provider/MCP/采集仍需执行各自更严格的协议、主机、DNS 和重定向检查。
- 生产 audit 的 high/critical 为硬门禁。Next 16.2.11 内置 PostCSS moderate 例外到 2026-08-23，禁止通过 Next 9 降级或 `audit fix --force` 处理。

# 2026-07-23 · 0.2.0 升级治理基线

- `develop` 是 P3 之后的开发集成分支；安全、可靠性、性能与架构收口必须保持独立提交和回滚边界。
- `docs/dependency-maintenance.md` 负责依赖策略，`docs/upgrade-roadmap.md` 负责本轮状态与证据，changelog/agents 只保留摘要。
- CI 显式执行 typecheck、lint、contracts、build，并按桌面/移动拆分 E2E；P0 完成后生产依赖 audit 必须成为硬门禁。
- 依赖补丁不得使用 `npm audit fix --force`，Node.js 22、TypeScript 5、ESLint 9 与 Dexie v16 保持不变。

# 2026-07-23 · 可靠性与脱敏诊断

- 根错误边界不得渲染 `error.message`、堆栈或原始响应；用户可复制的内容只允许稳定类别、时间和框架 digest。
- API 可观测性保持本机、有界、内存态。只记录路由类别、阶段、耗时、状态码和错误类别，禁止为了诊断保存请求体、响应体、Cookie、Token、音频或 Vault 正文。
- Effect 初始化异步资源时使用可取消任务和卸载保护；不得通过 `react-hooks/set-state-in-effect` 注释绕过生命周期问题。

# 2026-07-23 · 包体与无障碍门禁

- 包体预算必须从生产清单按首屏实际资产计算，chunk 文件名只作证据展示，不能成为固定判断条件；基线增长上限为 5%。
- `experimental-analyze` 的模块总榜包含异步块，不能把其中的大模块误判为首屏依赖。应同时核对首屏清单和静态 import 契约。
- 低频预取只允许由 hover/focus 意图触发代码加载，不得顺带读取 repository 或发业务请求。桌面与 390×844 移动关键页必须保持 axe serious/critical 为零。

# 2026-07-23 · 领域类型与 facade 收口

- 新业务必须直接从 `types/domains/*` 引用；`types/review.ts` 只保留历史兼容出口，架构契约阻止业务依赖回流。Node 契约测试使用领域入口时保留显式 `.ts` 扩展。
- Provider 与 Obsidian 拆分必须保持原 facade 导出、错误语义和持久化顺序。纯 helper 不持有 Vault 句柄，语音 mapper 不改变厂商鉴权或请求字段。
- 每个实现模块继续限制在 500 行以内；类型和 facade 整理不是升级 Dexie 的理由，`review_workspace` 维持 v16。

# 2026-07-26 · 生产依赖审计门禁经验

- npm audit 返回端点错误 JSON、非法 gzip 或无漏洞计数时不能视为“零漏洞”；只有包含 `metadata.vulnerabilities` 的报告才是有效审计结果。
- npm audit 基础设施异常时可使用官方 Bulk Advisory API，并从 lockfile v3 只收集实际生产依赖及嵌套版本；两条路径都失败时必须失败关闭。
- 新 high 公告会立即使既有 moderate 例外失效。`js-yaml@5.2.2` 与 Next 子树 `postcss@8.5.23` 是本轮修复边界，禁止通过降级 Next 或 `audit fix --force` 绕过。
- Next 与 `eslint-config-next` 必须同补丁更新；ESLint 保持 9、TypeScript 保持 5、Node 类型保持 22。Playwright 浏览器基线与 Lucide 视觉资产应使用独立变更验证。

# 2026-07-26 · 本机密钥与对话控制经验

- 浏览器本机密钥保护应保存不可导出的 `CryptoKey`，密文再用 AAD 绑定记录与字段；仅把 JWK 从一个 localStorage 键换到另一个位置不构成安全升级。
- 多存储位置共享旧主密钥时，迁移必须可重复执行，并在全量复核前保留旧 JWK。部分记录已迁移到 v2 是安全的恢复点，不应为了追求事务外观回写旧密文。
- 模型运行参数中，高频调整的推理强度适合独立滑杆；拖动过程属于瞬时 UI 状态，持久化只发生在交互结束，并继续进入会话级串行回滚链路。
- 右键菜单不应以指针坐标形成第二套定位规则。右键和显式按钮都解析同一个行操作锚点，移动端则忽略桌面坐标统一进入底部层。
- 模型输出 Markdown 必须把排版能力与 HTML 执行能力分开：GFM 可用，原始 HTML、`dangerouslySetInnerHTML` 和页面权限继承不可用。

# 2026-07-26 · 中性交互与外联安全经验

- 单色交互应从共享 token 和基础组件收口，不能只在页面里逐个替换。发布契约应明确禁止焦点、选择和主操作重新引用蓝色，同时允许品牌与数据编码保留颜色。
- CSS 二级菜单必须使用足够具体的直接子选择器覆盖底部层基础规则；只写 `.conversation-tree-move-menu` 会被 `.conversation-tree-drawer section` 的高特异性保留为相对定位，导致子菜单落到一级菜单下方。
- 凭据健康检查只解密并立即丢弃结果；恢复 CTA 打开高级设置并聚焦空的 Key 输入。保存失败不得覆盖旧密文，保存成功后再刷新当前记录健康状态。
- 安全导出使用表允许清单而不是遍历 Dexie 全表；字段清理仍作为第二道防线。连接导出前判断记录类型，再删除 `maskedKey` 等字段并写入重新配置标记。
- 出站 URL 校验必须同时覆盖协议、内嵌凭据、IP 分类和 DNS 全部结果。当前 Provider/MCP 不跟随重定向；若未来允许跳转，必须逐跳复用同一策略并设置硬上限。
- 浏览器视觉检查除截图外要记录菜单/锚点几何、控制台、页面级横向溢出和焦点计算样式；移动端底部菜单项保持至少 44px。

## 2026-07-26 · AI 连接保存恢复经验

- 跨凭据迁移失败不能成为保存新凭据的全局事务锁。严格迁移负责最终清理，交互路径应返回部分状态，并把新 Key 的加密与目标记录写入隔离完成。
- 编辑连接的身份由稳定 ID 决定，厂商是可变配置。厂商切换必须清空旧鉴权、应用新默认端点并强制重输 Key，不能通过生成新 ID 规避更新语义。
- 表单错误应出现在动作附近并通过 `aria-live` 持久表达；缺少必填凭据时直接展开、聚焦和滚动到输入框，避免无可见结果。

## 2026-07-26 · 额度短事务与组件示例经验

- 启停开关不能复用“保存、迁移、验证、刷新”的长链路。先用单记录短事务落库，再把可取消网络任务交给运行时；网络失败只影响状态，不回滚用户意图。
- 新凭据保存不应等待共享旧凭据迁移。严格迁移继续负责最终删除旧 JWK，交互写入只对当前字段使用 v2 加密。
- 开发示例应在真实容器挂载前分流，并用纯内存回调展示输入后状态；只把假数据藏在真实容器内部仍可能触发 repository、解密或外联。
- 公考总览不承担统一示例目录；只有显式登记 fixture 的具体模块显示自己的“真实数据/模块示例”选择，禁止从一个模块跨选另一个模块的示例。
- 嵌入式详情响应式应依据 container width，而不是浏览器 viewport；矮屏还需同时限制高度并提供内部滚动。

## 2026-07-27 · 统一 Chrome 与工作区几何经验

- 页面模式切换不应通过条件分支返回不同 `WorkspaceShell`；共享外壳应常驻，路由只替换导航与内容插槽，否则位置、抽屉焦点和滚动上下文会随重挂载跳动。
- 顶部区与侧栏需要视觉连续时，应由共同祖先绘制唯一底层；两个相邻 surface 分别叠加弥散，即使颜色相同也会在交界形成可见接缝。
- “更高但不贴顶”应成为明确设计令牌和几何契约。本项目桌面固定 `12px`，移动端明确不用该令牌，避免依赖顶栏高度或偶然 margin。
- AI 表格动作列先按最长恢复文案分配槽位，再让中等宽度提前转为列表；移动端隐藏破坏性动作会造成能力缺失，响应式只能重排，不能删除。
- 外壳重构的真实浏览器证明至少同时覆盖 DOM 节点身份、展开/折叠几何、1115×792 中间宽度、390×844 焦点抽屉、弥散开关和最长动作文案。

# 2026-08-02 · 对话轨道、插件生命周期与桌面标题栏经验

- 对话主题属于阅读定位辅助，不应永久占据内容列。桌面用短横线表达位置，标签只在 hover/focus 展开；可访问名称始终包含主题序号和完整标题，移动端继续使用明确的主题抽屉。

# 2026-08-09 · Host 与 Application 边界经验

- renderer 业务代码不得直接读取 Electron preload global；只有 `app/platform/desktop/` 和 ambient 类型声明可以出现 `reviewDesktopVault` / `reviewDesktopWindow`。
- Host 环境解析必须惰性执行，避免服务端渲染或测试在模块初始化阶段访问 `window`。Web adapter 只声明浏览器实际具备的能力，缺失能力返回 `undefined`。
- Host capability 的类型不能扩大 preload 权限；新增能力必须先有独立安全设计，继续保留 context isolation、sandbox、sender 校验和 permission/navigation boundary。
- 当前 Web 与 Electron 共用视觉 chrome，浏览器不得伪造系统窗口按钮或 IPC。只有出现真实视觉分叉时，才增加默认关闭、仅开发环境的 preview 样式开关。
- Application Layer 只承载真实的多步骤业务编排；单次 repository 转发不应为追求分层而包装。首批候选优先面试、自动化和导入，对话发送链路待模式稳定后迁移。
- Interview Application 首批采用显式窄函数依赖：Use Case 负责编排 repository、AI 与 timer，React Hook 只保留 busy、输入校验、刷新、通知、示例模式和评分触发。`shouldEvaluate` 由提交用例返回，禁止反向调用 Hook。
- 跨 IndexedDB 与外部 AI 的失败保持部分提交：不回滚已确认 Candidate Turn、不自动重试请求。稳定错误必须标记失败步骤与已完成结果；无幂等键时不得宣称用户再次提交不会重复。

- 主题标题、助手摘要与附件全部从 `ConversationTurnTimeline` 派生；常驻高亮永远是数组最后一项，阅读旧消息不得改写它。
- 上下文预算、真实发送与压缩必须复用规范化会话装配边界；压缩保留最近六轮原文，只附加会话记录且不得升级 Dexie v16 或保存厂商专有状态。
- 插件市场只做发现、校验和安装；一级目录默认不选中插件，行主体、开关与三点菜单必须保持独立交互区。
