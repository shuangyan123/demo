# 全应用 UI/UX 信息密度审计

## 目标与基线

本审计用于减少首屏重复说明和无效操作，不以“全部卡片化”或统一放大留白代替信息架构。AI 连接与额度页作为紧凑设置基线：

- 首屏只保留当前状态、一个主操作和明确下一步；
- 解释性内容优先进入 tooltip、详情层或原生 disclosure；
- 桌面高频表格保持 32–36px 信息行，粗指针操作至少 44px；
- 品牌图标只表示厂商，Lucide 图标只表示应用操作；
- 空状态必须说明原因并提供一个可执行下一步。

## 页面审计

| 页面 | 当前风险 | 首屏保留 | 下沉内容 | 优先级 |
| --- | --- | --- | --- | --- |
| 核心工作台 / 新对话 | 侧栏、空白草稿和工具提示同时解释入口，注意力分散 | 最近任务、输入区、当前项目状态 | 使用说明、低频工具解释 | P0 |
| 公考首页 | 学习链路卡片文案重复，状态与动作容易混在一起 | 六步学习链路状态、唯一推荐下一步 | 每步方法说明、数据来源 | P0 |
| 错题 / 复盘 | 筛选、题目摘要和复盘说明争夺首屏 | 当前筛选、题目列表、开始复盘 | 计时规则、导出解释、历史统计 | P1 |
| 知识库 | 导入、训练、Obsidian 和 AI 演进说明较长 | 搜索、资料列表、待确认数量 | 同步原理、冲突规则、AI 提案诊断 | P1 |
| AI 辅导 / 面试 | 设备、隐私、语音和教学流程说明同时出现 | 当前任务、输入设备状态、开始/继续 | 媒体隐私细则、评分依据、历史说明 | P1 |
| 已安排 | 调度规则和失败恢复说明容易压过任务列表 | 任务状态、下次运行、创建任务 | Cron/时区说明、恢复原因详情 | P2 |
| 设置 | 各分区说明密度不一致，诊断页操作较多 | 当前设置项、状态、主操作 | 来源、许可、错误细节 | P2 |

## 分期方案

### P0：核心工作台与公考首页

- 为桌面和 390px 移动端分别生成确认稿。
- 合并重复入口说明；空白草稿只保留一个起始提示。
- 公考首页每个链路节点只显示名称、状态和一个动作，完整解释进入详情。
- 验收：首屏无横向滚动、每个区块不超过一个主按钮、键盘路径可完成新对话和推荐下一步。

### P1：学习内容与辅导

- 统一错题、知识列表的搜索与筛选工具栏，避免板块筛选在多处重复。
- 辅导和面试把设备状态、当前轮次和反馈动作置顶；隐私与评分说明折叠。
- 保持现有 controller、repository 和默认连接边界，不借 UI 改版升级 Dexie。
- 验收：列表首屏可直接操作，说明层不遮挡内容，媒体权限拒绝后有明确恢复动作。

### P2：已安排与设置

- 已安排列表优先展示运行结果和下一次时间，Cron、时区与失败诊断进入详情。
- 设置分区继续按信息密度使用独立宽度，不创建统一巨型卡片容器。
- 诊断页把安全恢复动作与只读说明分开，危险操作继续使用锁焦弹层。

## 后续设计与验证要求

- 每期先完成 1536×1024 与 390×844 的 Image-2 设计稿并确认，再实现。
- 每次改版记录允许的首屏文案清单，浏览器回归检查新增、删除和重排文字。
- 视觉回归至少比较布局、字体、颜色、图标、间距、移动端折叠和主操作层级。
- 每期运行 `npm run lint`、`npm run test:contracts`、`npm run build` 及对应 Playwright 流程。
