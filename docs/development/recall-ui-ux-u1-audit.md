# Recall UI/UX U1 现状审计

日期：2026-09-09
审计基线：`b20b8cce746b4482cd7b155d8c06186c59dfd3b5`（`origin/chore/recall-visible-brand-migration`）
环境：Node `v26.2.0` / npm `11.13.0`；浏览器基线为桌面 `1536×1024`、窄屏 `390×844`。这是开发期观察记录，不是发布验收。

## 观察到的现状

### A. 信息架构

- 侧栏首层是“新对话、搜索、已安排、插件”，学习能力被收在“项目 → 公考 → 模块”下；用户需要先展开项目，再展开模块组才能看到学习入口。
- 默认可见模块是总览、粉笔练习、学习数据、开始复盘、知识训练、面试训练；粉笔导入、知识库、AI 辅导、薄弱分析需要通过“添加公考模块”才能出现。
- “学习数据”实际合并错题、知识和薄弱分析；“开始复盘”才显示“错题复盘”，导航文案与产品能力名不完全一致。
- 导入和手动录入不是统一的材料入口：总览突出“粉笔导入”，多个学习页面重复出现“粉笔导入 / 手动录入”。

### B. 导航层级

- 桌面侧栏是稳定的工作台壳，但学习入口、项目/对话树和工具入口没有形成“学习优先、工具其次”的明显层级。
- 当前学习模块顺序基本沿 registry 顺序展示，已安排位于快捷入口而不是学习链路旁；对话树位于项目内部，入口“新对话”却在最上方快捷区。
- 设置采用独立侧栏模式，桌面清晰；移动端退化为设置分区下拉，功能完整但与应用侧栏的层级语言不同。

### C. 视觉层级

- 总览同时展示“下一步”、今日学习、公考学习链路、三项统计和多个详情组；学习链路七个节点视觉权重接近，首要行动没有持续占据最强层级。
- 侧栏的“新对话、搜索、已安排、插件”与学习项目入口使用相近的行式处理，工具和核心学习目的地竞争注意力。
- 展开侧栏时能看到 Recall 文本和副标题；收起后顶部只剩紧凑图形标记，产品品牌语义弱。现有 Recall 资产和 `错题复盘` 技术/产品身份不应被改写。

### D. 密度与间距

- 总览桌面首屏横向空间充足但纵向内容分散，链路区域占据较大高度；设置页相对稀疏。
- 导入页是明显的高密度多区工作台，账户同步、文件/截图、文本解析、草稿表格和详情同时出现；知识库也把编辑、内化、Obsidian 和模板工具连续铺开。
- 侧栏行高和移动触控尺寸已有基础约束，但增加全部可选模块后移动抽屉会变成长列表，分组和渐进展开更重要。

### E. 主次操作

- 空数据总览的“粉笔导入”能回答“下一步做什么”，但只有导入路径被突出；已有的复盘/训练/薄弱行动应继续由现有数据和 next-action 逻辑决定，不新增推荐语义。
- 学习页顶部重复放置导入与手动录入，缺少一个稳定的“添加学习材料”概念入口；导入页内部的“开始导入”仍应保留为页面动作。
- 插件、设置、搜索和新对话都是必要工具，但不应与核心学习工作流拥有同等的首层视觉权重。

### F. Context Panel

- 顶部栏始终提供上下文面板触发器；对话页打开后右侧显示“对话上下文”，包含会话资料和附加资料摘要，关闭按钮和 Escape/焦点机制由共享壳承载。
- 右侧面板当前是按视图注册的上下文能力，U1 只调整触发器和壳层呈现，不强制在不需要上下文的视图打开或新增 AI 面板内容。

### G. 学习流程连续性

- 总览的“公考学习链路”已经表达导入 → 错题复盘 → 知识沉淀 → 知识训练 → 对话辅导 → 已安排 → Obsidian 输出，但其中若干节点跳转到聚合视图或对话，侧栏又使用另一套命名。
- 现有 next-action 数据和链路按钮可复用；本阶段应统一壳层导航和文案，不改变学习状态、推荐排序或数据提交语义。

### H. 移动行为

- 390×844 下应用侧栏作为临时抽屉打开，选择可见导航后会关闭并显示目标内容；Escape 关闭后焦点恢复到侧栏触发按钮，body 滚动锁定/恢复行为存在。
- 抽屉内项目、模块和分区内容在同一纵向列表中，模块全部启用时需要较多滚动；主内容可见但导入、知识库等长页面仍需继续做无横向溢出检查。
- 设置移动端使用“设置分区”选择器，目标清晰但与应用侧栏的分组结构不一致。

### I. 可访问性、键盘与焦点

- 现有壳层使用 `nav`、`aside`/移动 `dialog`、`aria-current`、`aria-modal`、`inert` 和焦点陷阱；移动抽屉 Escape 与焦点恢复基线通过。
- 侧栏的项目/模块使用原生 `details/summary`，但分组标题、学习组与工具组仍可用更明确的语义标签和 aria 关系表达。
- 收起桌面侧栏时文字被隐藏，图标按钮依赖 tooltip/aria-label；新增入口必须保留可访问名称、键盘顺序、可见 focus 和最小触控尺寸。

### J. 术语与 affordance 一致性

- 同一能力在不同位置出现“学习数据 / 错题库”“开始复盘 / 错题复盘”“粉笔导入 / 导入”等称呼。
- “模块”管理入口与“添加学习材料”是不同概念：前者管理可见能力，后者应只选择已有导入/手动录入动作，不能暗示安装新系统。
- 当前状态提示会在跨页操作后短暂显示于主内容上方；壳层重排时需避免把 toast、context panel 或移动抽屉变成竞争性固定表面。

## U1 实施边界

1. 在现有 `ReviewWorkspaceAppSidebar` 与 `WorkspaceShell` 架构内重排分组、入口顺序、品牌位置和当前项语义；不改业务 controller、数据 schema、Electron/preload 或 provider。
2. 将学习入口集中在“学习”层级，并对现有 registry 文案做最小的产品术语对齐：保留 review 视图名“错题复盘”，不删除任何模块或深链。
3. 增加导航层面的“添加学习材料”入口，复用现有导入与手动录入回调；导入 provider、Fenbi import、手动录入页面和原有直接入口保持不变。
4. 让总览的现有“下一步”在壳层中更突出，调整信息分组与密度但不新增推荐引擎、不制造学习数据。
5. 保留按视图注册 ContextPanel 的架构，只改善共享触发器/面板的层级和响应式呈现。

## 明确留到后续

- 不重做导入、知识库、面试、AI 辅导、薄弱分析等 feature page 的内部信息架构。
- 不把聚合的“学习数据”拆成新的业务页面或新持久化模型；只在导航层提供更清晰的入口命名。
- 不引入新的状态管理、CSS 框架、依赖、schema、Electron 能力、release/workflow 变更或 PR #126/#127 的 E2E 文件修改。
